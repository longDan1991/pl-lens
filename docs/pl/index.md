# PL 总书

以 **TypeScript / Python** 为思维锚点，以 **C** 为底层标尺，横向拆解 **TS / Python / Go / C / Rust / C++** 的核心设计取舍，主线指向**确定性低延迟与高性能系统工程**。

## 为什么是这 6 章？（一条工程因果链）

这 6 章不是散装专题，而是从“写业务”沉到“写确定性低延迟系统”的前置依赖链：

1. **0. 坐标系（心智模型 / 尾延迟）—— 先纠偏**：打破托管运行时直觉，明确核心指标是 P99.9 尾延迟确定性而非平均吞吐。
2. **1. 内存真相（栈与堆 / 缓存行 / 未定义行为 / 浮点数）—— 建标尺**：用 C 钉死硬件与内存事实，不懂栈帧、64B Cache Line、对齐空洞与 UB，后续设计全靠死记硬背。
3. **2. 资源管理（所有权 / 移动语义 / 智能指针 / 零堆分配）—— 解核心矛盾**：去掉 GC 后解决“谁在何时释放内存”，对比 Rust 借用检查与 C++ RAII/移动语义，落到热路径零堆分配（定长池）。
4. **3. 类型抽象（错误模型 / 零拷贝视图 / 派发成本）—— 拿零成本抽象**：在不用异常、不拷贝内存、不走虚表跳转的前提下，把大多数 Bug 拦在编译期。
5. **4. 并发模型（数据竞争 / 内存序 / 无锁队列 / 协程 / 忙轮询）—— 压榨多核与 I/O**：从线程安全下沉到 CPU 乱序与 `Acquire-Release` 内存序，划清数据面（无锁/忙轮询）与控制面（协程/`epoll`）边界。
6. **5. 生产工程（构建与链接 / 内存排错 / 性能剖析 / Python FFI）—— 过上线门槛**：补齐构建链接、Sanitizers/`miri`、`perf` 硬件计数器与反汇编，最后用 FFI 接回 Python 生态。
