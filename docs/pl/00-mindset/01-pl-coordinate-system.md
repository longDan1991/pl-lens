# 0.1 为什么你的直觉在系统语言里全线失效？

> **副标题**：六门语言的 PL 坐标系：运行时、内存与抽象成本全景

从 TS / Python 切到 Rust / C++，常觉得处处受阻。**问题不是语法不熟，而是心智模型变了。**

TS / Python 有托管运行时：对象默认在堆上，变量是引用，GC 管生命周期。Rust / C++ 无运行时兜底，每行代码直接对应内存布局与 CPU 指令。

> 若还不熟单门语言基础语法，可先切右上角进入对应专书（如 [Rust 专书](/rust/)），再回来看跨语言对比。

## 一、6 门语言的 PL 坐标系

主流语言的差异集中在 7 个正交维度：

| PL 维度 | TypeScript | Python | Go | C | Rust | C++ |
|---|---|---|---|---|---|---|
| **内存管理** | Tracing GC (V8) | 引用计数 + 循环 GC | 逃逸分析 + 三色标记 GC | 手动 (`malloc`/`free`) | 编译期所有权 / 借用检查 | 手动 + RAII / 智能指针 |
| **默认语义** | 对象引用 / 原始值 | 堆对象引用 | 值语义（含显式指针） | 值语义（裸指针） | 值语义 + 默认 Move | 值语义 + 默认 Copy |
| **类型检查** | 静态（编译后擦除） | 动态 | 静态强类型 | 静态弱类型 | 静态强类型 + 局部推导 | 静态强类型（隐式转换多） |
| **类型等价** | Structural | Duck Typing | 接口 Structural / 其余 Nominal | Nominal | Nominal | Nominal |
| **泛型实现** | 类型擦除 | 统一 `PyObject*` | 字典 + GC Shape 单态化 | 宏 / `void*` | 编译期完全单态化 | 模板实例化（单态化） |
| **多态派发** | 原型链 / Hidden Class | 属性字典 | Interface 胖指针 | 函数指针 | 静态派发 / `dyn` 胖指针 | 模板静态派发 / `vptr` 虚表 |
| **错误处理** | 异常 (`throw`) | 异常 (`raise`) | 多返回值 `error` | 错误码 / `errno` | `Result<T, E>` | 异常 / `std::expected` |

## 二、三个核心断层

### 1. 引用语义 vs 值语义：`b = a` 做了什么？

::: code-group

```ts [TypeScript]
// 复制引用：a 和 b 指向堆上同一个数组
const a = [1, 2, 3]
const b = a
b.push(4) // a 变为 [1, 2, 3, 4]
```

```python [Python]
# 复制引用：a 和 b 绑定同一个 PyListObject*，引用计数 +1
a = [1, 2, 3]
b = a
b.append(4)  # a 变为 [1, 2, 3, 4]
```

```go [Go]
// Slice 是 24 字节值类型（ptr/len/cap）：值拷贝头，共享底层数组
a := []int{1, 2, 3}
b := a
b[0] = 99           // a[0] 也变为 99
b = append(b, 4)    // 若触发扩容，b 指向新底层数组，与 a 脱钩
```

```cpp [C++]
#include <vector>

std::vector<int> a = {1, 2, 3};
std::vector<int> b = a;            // 默认深拷贝：触发堆分配 + 逐元素复制
std::vector<int> c = std::move(a); // 显式移动：转移内部指针，a 变为空壳
```

```rust [Rust]
let a = vec![1, 2, 3];
let b = a;         // 默认 Move：拷贝 24 字节头，a 编译期失效
// println!("{:?}", a); // 编译报错：borrow of moved value
let c = b.clone(); // 深拷贝必须显式写出
```

:::

- **C++ 默认深拷贝**：按值传参（`void f(std::vector<int> v)`）会暗中触发堆分配。
- **Rust 默认 Move**：强制把昂贵的深拷贝显式写成 `.clone()`，同时在编译期拦截 Move 后误用。
- **Go 切片折中**：拷贝 24 字节头但共享底层数组，`append` 扩容时才分家，易踩“共享修改”坑。

### 2. 静态语义 vs 运行期表示

TS 类型在编译为 JS 后完全擦除，V8 运行期仍面对动态对象。
C / C++ / Rust / Go 的结构体类型直接决定内存字节布局：

- `Point { x: f64, y: f64 }` 占连续 **16 字节**，无对象头、无属性字典。
- 100 万个 `Point`：
  - Rust `Vec<Point>` / C++ `std::vector<Point>` / Go `[]Point`：连续 **16 MB** 内存，CPU 缓存命中率高。
  - Python `list[Point]`：100 万个指针 + 100 万个分散堆对象（含引用计数、类型指针、`__dict__`），体积超 **100 MB**，大量 Cache Miss。

#### 运行期反射 vs 裸字节内存（为什么系统语言没有“通用打印 / 判等”？）

- **Python / JS 对象自带“说明书”**：堆上对象携带类型指针与属性表（如 `PyObject` 的 `ob_refcnt`、`ob_type`、`ob_dict`），`print(p)` 可在运行期查表拿到类名与字段名。
- **Rust / C++ 编译后烧掉元数据**：`Point { x: 1, y: 2 }` 在内存里只剩连续 8 个裸字节（`01 00 00 00 | 02 00 00 00`），运行期不知道字段名，也不知道这 8 字节是两个 `i32` 还是一个 `f64`。
- **为什么不能默认按逐字节 `memcmp` 判等**：
  1. **对齐空洞（Padding）**：结构体字段间可能存在未初始化的填充字节（详见 [1.2 结构体对齐](/pl/01-memory-truth/02-alignment-cache-line)）；
  2. **堆指针字段**：两个内容相同的 `String` 指向不同堆地址，按字节比会误判不等；
  3. **浮点语义**：IEEE-754 规定 `NaN != NaN`（详见 [1.4 浮点陷阱](/pl/01-memory-truth/04-float-and-fixed-point)）。
- **编译期代码生成**：Rust 用 `#[derive(Debug, PartialEq)]` 趁编译期字段信息还在，只为需要的能力生成对应机器码，然后丢弃元数据（见 [Rust 1.1 语法符号速查](/rust/01-syntax/01-syntax-symbols)）。

### 3. 泛型擦除 vs 单态化

- **TS**：类型擦除，运行期只有一份函数。
- **Go**：按 GC Shape（指针/非指针内存形状）分组单态化 + 字典传类型信息，平衡编译速度与运行开销。
- **Rust / C++**：按具体类型完全单态化（`max<i32>` 与 `max<f64>` 生成两份机器码）并内联。代价是编译慢、二进制变大；收益是零派发开销。

## 三、工程切换清单（4 条规则）

1. **看见赋值与传参先看字节成本**：C++ 默认传 `const T&` / `std::string_view` / `std::span`；Rust 默认传 `&T` / `&str` / `&[T]`；Go 大结构体传指针 `*T`。
2. **数据尽量打平连续存放**：优先 `Vec<T>` / `std::vector<T>` / `[]T`，减少指针跳转（Pointer Chasing）。
3. **少写循环引用图结构**：双向链表与父子互引在 Rust 撞借用检查，在 C++ 易悬垂；工业界首选**连续数组 + 整数索引**。
4. **区分编译报错与运行期 UB**：Rust 报错是编译期兜底；C++ 过编译不代表安全，必须开 ASan/UBSan。

## 四、面试连环追问 Q&A

### Q1：TS 和 Rust 都是静态强类型，为什么性能差距巨大？

- **结论**：静态类型检查只决定编译期查错；决定性能的是**类型是否下沉为连续内存布局与单态化机器码**。
- **原理**：TS 类型在编译后擦除，V8 仍需对象头、装箱、GC 与 JIT 推测（Deopt 会退化）；Rust/C++ 直接按固定字节偏移寻址并单态化内联，无运行时税。

### Q2：Rust 默认 Move、C++ 默认 Copy、Go Slice 浅拷贝，工程上各有什么坑？

- **C++**：隐式深拷贝拖垮性能；`std::move` 后源对象仍可被误读（有效但未指定状态）。
- **Rust**：语法摩擦高，但编译期杜绝隐式深拷贝与 Use-After-Move。
- **Go**：多变量共享底层数组，未扩容时互相污染，扩容后突然脱钩。

### Q3：为什么核心系统数据结构很少用结构化类型（Structural Typing）？

- **结论**：结构化子类型无法在零开销前提下保证固定字段偏移。
- **原理**：不同结构体只要含同名字段就能传入同一函数时，运行期必须查偏移（Python 字典、V8 Hidden Class、Go Interface 胖指针）。名义类型配合单态化可直接编译为固定偏移寻址（如 `[rdi + 8]`）。
